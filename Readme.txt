┃ ★ 毎週末の開催ルーティン（毎週の予想時は、この手順だけ上から順に実行）    ┃
┗━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┛
※過去データ（7,770万行）は作り直さず、今週の指数と出馬表だけを数秒で反映します。
※過去走のマイニング（タイムM・対戦M）は毎週取得する必要はありません（半年〜1年ごとの更新時のみ）。

【事前準備】プロジェクトフォルダへ移動し、Webアプリを起動しておく
  cd ~/Downloads/self-dev/docker/shisu/docker_shisu_replace
  docker run --rm -p 127.0.0.1:8000:8000 -v "$(pwd)":/app csv_processor_shisu python app.py

--------------------------------------------------------------------------------
STEP 1：今週の「外部指数」を取得して ext_indices/ に揃える（※出馬表処理の前に必須）
--------------------------------------------------------------------------------
出馬表を処理する前に、今週分の外部指数データを ext_indices/ に揃えます。

  ① スクレイピング指数（オメガ・keibaAI・かよちん・吉馬6種）＆ 安井サロンExcel：
     1. TARGET「出馬表分析」→「★5タブ」で今週の全レースを全選択し、ベースCSVを
        `ingest_in/base/` に出力する（必須列：レースID(新), 日付S, 枠番, 馬番, ワーク1）。
        ※安井サロンExcelがある場合は `ingest_in/yasui/` に置く。
     2. ブラウザで http://localhost:8000/ingest を開く。
     3. ベースCSV（と安井Excel）を選び、取得したい指数（①Ω・②吉馬・③かよちん・④keibaAI）に
        チェックを入れて実行する（keibaAIは開始ID・終了IDを入力）。
     → 選んだ取得元は【同時に】取得します（サイトが別なので待ち時間が重ならない。全体の時間は
        いちばん遅い取得元の時間ほど。サイトごとのアクセス間隔は今までどおり守ります）。
        ログは行ごとに「Ω指数:」「吉馬:」などの取得元の名前が付きます。
     → 取得完了と同時に、自動的に `ext_indices/` の各指数フォルダへ格納されます。

  ② TARGET・外部ソフトから取得する指数（StridePlus 12種・ZI・GoldAirplane・BCindex）：
     最新の指数CSVファイルを、手動で `ext_indices/` 配下の各フォルダに配置してください。
     ・StridePlus（sav, st, gokei, tenkai, siagari, senko, tsuiso, jikyu, jizoku, shunpatsu, mae_stime, ato_stime）
       → `ext_indices/StridePlus/`
       ※ボーダーのファイル（st_border*.csv・siagari_border*.csv など名前に border の付くもの）は
         一緒に置いたままで構いません。指数としては読みません（ST指数・仕上りを上書きしません）。
     ・ZI → `ext_indices/ZI_DATA/`
     ・GoldAirplane → `ext_indices/GoldAirplane/`
     ・BCindex → `ext_indices/BCindex/`

--------------------------------------------------------------------------------
STEP 2：TARGETから今週の「出馬表CSV」を出力して entries_in/ に置く
--------------------------------------------------------------------------------
  TARGETで「開催ひらく」→「JV一括取得」→「マイニング予想」
  →「出馬表分析」→「★4タブ」→ **【重要】「マイニングの読み込み」を実行**
  → 右クリック「全て選択する」→「選択範囲をファイルに出力（CSV）」で `entries_in/` に保存。
  （ファイル名例：`entries_in/shisu_20261108_1.csv`）

  ※注意：マイニング（タイムM・対戦M）は外部CSVではなく、この出馬表CSVの列から直接取得します。
          必ず★4タブで「マイニングの読み込み」を行ってからCSV出力してください。
          （それ以外の外部指数1〜4をTARGET側で読み込む必要はありません。STEP 1で揃えた
            `ext_indices/` からプログラムが自動で全馬に結合します）

--------------------------------------------------------------------------------
STEP 3：出馬表の偏差値計算 ＆ DB反映（別タブで2コマンド実行）
--------------------------------------------------------------------------------
Webアプリを起動したまま、ターミナルの別タブ（Cmd + T）で以下の2つを実行します。

  # 1) 出馬表に ext_indices/ の全外部指数を結合し、偏差値・順位・帯を計算する
  docker run --rm -v "$(pwd)":/app csv_processor_shisu python calc_entry_hensachi.py --merge-only --clean

  # 2) DBの出馬表と事前照合（xjoin）だけを更新する（古い出馬表は --prune で自動削除）
  docker run --rm -v "$(pwd)":/app csv_processor_shisu python build_db.py --entries-only --prune

  → 完了後、ブラウザで http://localhost:8000/entries を開けば、今週の出馬表・条件ヒット馬・WEDGE一覧が見られます！

--------------------------------------------------------------------------------
STEP 4：【当日・馬体重発表後】マイニング確定値が出たら出馬表を差し替える（差分更新）
--------------------------------------------------------------------------------
レース当日（馬体重発表と同じタイミング）にマイニングの「確定値」が出たら：
  1. TARGETの★4タブでマイニング（確定値）を読み込み直し、`entries_in/` の出馬表CSVを上書き出力する。
     （※外部指数はすでに `ext_indices/` にあるため再取得不要）
  2. 以下の2コマンドを実行する（--mining-only ＝ タイムM・対戦M だけの差分更新）：

  docker run --rm -v "$(pwd)":/app csv_processor_shisu python calc_entry_hensachi.py --mining-only
  docker run --rm -v "$(pwd)":/app csv_processor_shisu python build_db.py --entries-only --mining-only

  → Webアプリは起動したままでOK。ブラウザをリロードするだけで確定値が反映されます。

  ・--mining-only がすること：
      calc_entry_hensachi … STEP 3 で作った entries_out/entries_merged_hensachi.csv を読み、ext_indices/ は読み直さずに、
                            タイムM・対戦M の値・順位・偏差値・帯と、馬体重・増減などの基本の列だけを入れ替えて上書きします。
                            ほかの外部指数の列（計算済み）はそのまま残ります。
      build_db            … 出馬表のテーブルを入れ替え、事前照合（xjoin）は タイムM・対戦M の行だけを消して照合し直します
                            （ほかの約31指数の行は触りません。時間は全部やり直すときのおよそ 2/33）。
  ・--mining-only は `--indicators タイムM,対戦M` の短縮形です（`--indicators オメガ指数` のようにほかの指数も指定できます）。
  ・マイニング以外も変わっていたときは、自動で全部の計算・全部の照合に切り替わります（結果は STEP 3 と同じ。時間だけ STEP 3 並みにかかります）：
      calc_entry_hensachi … STEP 3 を一度も実行していない（統合ファイルが無い）／出馬表に馬が増えた・レースから馬が消えた
      build_db            … 騎手の乗り替わり・枠・前走の条件・ほかの指数の順位など、照合に関わる値が前の照合のときから変わっている
                            ／成績表を作り直したあと／前の実行が途中で止まったあと／前の版で作った照合結果（最初の1回だけ）
    どちらに切り替わったかは、実行時の [INFO] の行に出ます。つまり STEP 4 はいつもこの2コマンドで構いません。



--mining-only だけだと「タイムM・対戦M」の2指数しか見ないため、本日追加した安井式のデータが無視されてしまいます。
しかし、--mining-only に加えて --indicators で安井の8指数を指定すれば、他の24指数は一切再計算せず「マイニング2種＋安井8種」の計10指数だけを高速で差分更新できます。
STEP 3のように全34指数を1から計算し直す必要はありません（所要時間はフル実行の約3分の1以下で終わります）。
1. いま（または馬体重発表後に）実行するコマンド（マイニング2種 ＋ 安井8種のみ差分更新）

以下の2コマンドをそのままコピペして実行してください。

# 1) 統合出馬表の「タイムM・対戦M」と「安井8指数」だけを差し替える
docker run --rm -v "$(pwd)":/app csv_processor_shisu python calc_entry_hensachi.py --mining-only --indicators 安井_ランク,安井_スピード,安井_スタミナ,安井_パワー,安井_根性,安井_賢さ,安井_体力,安井_やる気

# 2) DBの照合結果（xjoin）も「タイムM・対戦M」と「安井8指数」の行だけを作り直す
docker run --rm -v "$(pwd)":/app csv_processor_shisu python build_db.py --entries-only --mining-only --indicators 安井_ランク,安井_スピード,安井_スタミナ,安井_パワー,安井_根性,安井_賢さ,安井_体力,安井_やる気

# 事前準備：Dockerイメージのビルド（初回、または Dockerfile / requirements.txt 更新時のみ）
docker build -t csv_processor_shisu .

docker run --rm -v "$(pwd)":/app csv_processor_shisu python -m pytest


■ D. 半年〜1年ごとに過去データを追加するとき（raw_csv/ への配置）
------------------------------------------------------------------------
※過去走のマイニング（タイムM・対戦M）や前走データは、半年〜1年に1回まとめて追加します。
※TARGET ★6タブで追加の期間を出し、raw_csv/ に置くだけです（/ingest 画面の下部からアップロードも可）。
  replace_csv_ver3.py（下の A の Step 1）が最初に自動で csv_files/全場_タイムM.csv・全場_対戦M.csv に統合します。
  ・基本CSV：名前に「タイム」「マイニング」（→ タイムM）か「対戦」（→ 対戦M）を入れる（例 タイムM_2027前半.csv）。
    同じ馬（レースID(新)）は後のファイルの行を使い、最大10年分（データの最新年の9年前以降）を残します。
  ・前走の列パッチ：前走データ読込は時間がかかるので、基本CSVは前走なしで出し、前走の列だけを別のCSVにして置く（→ 2章F）。
  ・済んだファイルは raw_csv/merged_done/ に自動で移ります。


■ A. 過去レース集計データを更新したときのフルリビルド手順
------------------------------------------------------------------------
※長時間処理になるため、別タブで `caffeinate -di` を実行してMacのスリープを防いでから回してください。

# Step 1: 基本CSV＋外部指数の結合・正規化・偏差値・22条件（csv_files/ ＋ ext_indices/ → master_csv/）
docker run --rm -v "$(pwd)":/app csv_processor_shisu python replace_csv_ver3.py --clean --workers 2
  ・raw_csv/ に未統合のファイルがあれば、最初に csv_files/全場_*.csv へ統合・前走の列パッチを反映します。

# Step 1.5（年1回の条件見直し時のみ）: 全掛け合わせ候補を採点して、使う family を選ぶ（→ 5章）
#   (a) 採点（重い。代表の指数で、all なら約5時間/master）
docker run --rm -v "$(pwd)":/app csv_processor_shisu python screen_families.py --space all --indicators タイムM,対戦M --workers 2 --export-selected
#   (b) 選抜基準だけやり直す（0.5秒。採点済みの screening_report.csv から再選抜）
docker run --rm -v "$(pwd)":/app csv_processor_shisu python screen_families.py --from-report --min-axis 1 --top-a 30 --export-selected

# Step 2: ベイズ集計＋WEDGE算出（master_csv/ → agg_csv/agg_master_{地域}_{指数名}.csv.gz）
docker run --rm -v "$(pwd)":/app csv_processor_shisu python aggregate_stats_ver2.py --clean --workers 2 --compact-min-count none --compact-min-wedge 1.0
  ・途中で止めた（Ctrl+C 等）ときは、--clean を --resume に変えれば済んだ master を飛ばして続きから再開できます：
      docker run --rm -v "$(pwd)":/app csv_processor_shisu python aggregate_stats_ver2.py --resume --workers 2 --compact-min-count none --compact-min-wedge 1.0

# Step 3: 出馬表の偏差値計算・1ファイル統合（entries_in/ → entries_out/entries_merged_hensachi.csv）
docker run --rm -v "$(pwd)":/app csv_processor_shisu python calc_entry_hensachi.py --merge-only --clean

# Step 4: DBの完全再構築（agg_csv/ ＋ entries_out/ → racing.db）
docker run --rm -v "$(pwd)":/app csv_processor_shisu python build_db.py --fresh


--------------------------------------------------------------------------------
2. TARGETからの入力CSV作成手順と、外部指数CSVの置き方
--------------------------------------------------------------------------------

＜A. 過去レースの基本CSV（csv_files/ または raw_csv/ に置くファイル）＞
  TARGETから出すのは次の2本だけです（★6タブ形式）。
  （1）レース検索 → ★6タブ（頭数10頭以上・障害レースを含めない条件で検索）
  （2）外部指数の欄に ①マイニング（タイムM）を読み込んで「レース一覧★画面イメージ（csv形式）」で出力
  （3）同じく ②対戦型マイニング（対戦M）で出力
  ・出力する列に「単勝配当」（単勝オッズの隣）と「複勝配当」（複勝シェアの隣）を追加しておくこと。
  ・追加の期間は raw_csv/ に置けば replace が csv_files/全場_タイムM.csv・全場_対戦M.csv に統合します。

＜B. 外部指数CSV群（ext_indices/ に置くファイル）＞
  ext_indices/ の下に、フォルダ名かファイル名で指数が分かるように置きます。
  ┌──────┬────────────────────────────┬──────────────────────────────────┐
  │ 形式 │ ファイルの中身                         │ 対象の指数（置き方の例）                             │
  ├──────┼────────────────────────────┼──────────────────────────────────┤
  │  A   │ レースID(新)18桁, 指数値               │ オメガ指数（OMEGA/）、かよちん指数（kayochin/）、    │
  │      │ ※/ingest から自動コピーされる形式     │ keibaAI指数（keibaAI/）、吉馬6指数（kichiuma/）、    │
  │      │                                        │ 安井8指数（yasui/）                                  │
  ├──────┼────────────────────────────┼──────────────────────────────────┤
  │  B   │ 旧ID10桁, 指数値, 順位（見出しなし）   │ StridePlus/ の下でファイル名の先頭で判定：          │
  │      │ 例 0520380101,54,6                     │  sav, st, gokei, tenkai, siagari, senko, tsuiso,     │
  │      │                                        │  jikyu, jizoku, shunpatsu, mae_stime, ato_stime      │
  ├──────┼────────────────────────────┼──────────────────────────────────┤
  │  C   │ 12桁レースID, 馬1指数, 馬1順位, …      │ Gold（GoldAirplane/ または gold*.csv）              │
  ├──────┼────────────────────────────┼──────────────────────────────────┤
  │  D   │ 旧8桁レースID, 馬1指数, 馬2指数, …     │ BC（BCindex/）、ZI（ZI_DATA/）                       │
  └──────┴────────────────────────────┴──────────────────────────────────┘

＜C. 今週の出馬表CSV（entries_in/ に置くファイル）＞
  開催ひらく → JV一括取得 → マイニング予想 → 出馬表分析 → ★4タブ → マイニングの読み込み
  → 右クリック → 全て選択する → 選択範囲をファイルに出力（CSV）
  （ファイル名例：shisu_YYYYMMDD_1.csv。マイニング値だけの1本でよい）

＜D. 外部指数スクレイピング用のベースCSV（ingest_in/base/ に置くファイル）＞
  ・過去走取得時：レース検索の★7タブ（障害除く）で出力。
  ・今週分取得時：出馬表分析の★5タブで全選択して出力。
  ・必須列：「レースID(新), 日付S, 枠番, 馬番, ワーク1」（※他の列が混ざっていても可）

＜E. ラップ指数計算用のラップCSV（ingest_in/lap/ に置くファイル）＞
  ・レース検索（障害除く）→ ★5タブで編集 → ワークデータ1に「レースのラップタイム」を読み込みCSV出力。
  ・必須列：「レースID(新), 日付S, 場所, 芝・ダ, 距離, クラス名, 年齢限定, 着順, 着差, 補正, レース印２, ワーク1」

＜F. 前走の列パッチCSV（raw_csv/ に置くファイル）＞
  TARGET の「前走データ読込」は時間がかかるので、基本CSV（A）は前走を読み込まずに出し、前走の列だけを
  別のCSVで出して raw_csv/ に置くと、全場_タイムM.csv と 全場_対戦M.csv の両方の同じ馬の行に横結合（補完）されます。
  （1）基本CSVと同じ抽出条件（頭数・障害・期間）でレース検索 → ★6タブ → 前走データ読込
  （2）出力する列を「レースID(新)」と前走の列（間隔・休み明け～戦目・前走場所・前芝・ダ・前距離・前走斤量・前走人気・
       前走着順・前走脚質・前走上り3F順・前走レース印３・前走レースID(新) など）だけにして CSV 出力
       ※「指数」列は入れないこと（「指数」列の無いCSVを列パッチとして自動判別します）
  （3）raw_csv/ に置いて replace_csv_ver3.py を実行（または /ingest 画面の下の欄で「統合する」）

3. システム全体像（内部で何をしているか）
--------------------------------------------------------------------------------
本システムは、過去データ側（replace / aggregate）と当日の出馬表側（calc_entry_hensachi / build_db）で
【完全に同一の共通パッケージ（shisu/）】を通して正規化・偏差値化・22条件・キー生成を行うことで、
表記ゆれの無いキー突合を実現しています。

  [Step 0] raw_csv/ の統合（replace_csv_ver3.py の最初・/ingest の画面）
  [Step 1] replace_csv_ver3.py（外部指数の結合・正規化・偏差値化・22条件 → master_csv/）
  [Step 1.5] screen_families.py（全掛け合わせ候補の採点・選抜 → selected_families.json）
  [Step 2] aggregate_stats_ver2.py（family × オッズ4区分集計・ベイズ推定・WEDGE算出 → agg_csv/）
  [Step 3] calc_entry_hensachi.py（出馬表への外部指数の結合・偏差値・帯付与＆横結合 → entries_out/）
  [Step 4] build_db.py（SQLite化・unified_all 統合・xjoin 事前構築 → racing.db）

4. 正規化ルール・順位帯・22条件・family（詳細リファレンス）
--------------------------------------------------------------------------------

(1) コース・クラス・重量・枠番の正規化ルール（shisu/normalize.py）
  ■ 重量種別：「別定」→「定量」に統合（「定量」「ハンデ」「馬齢」の3種）。
  ■ クラス名：「500万/1000万/1勝/2勝」→「1・2_勝」、「1600万/3勝/OP(L)」→「準OP・OP」、「G2/G3」→「重賞」、「G1」→「G1」。
              重量種別が「馬齢」かつ「1・2_勝」または「準OP・OP」の場合 →「1勝・OP」。
  ■ 枠番グループ：10〜13頭（1〜5内/6〜8外）、14〜16頭（1〜4内/5〜8外）、17〜18頭（1〜3内/4〜6中/7〜8外）。
  ■ 距離レンジ統合：福島芝17-18、新潟芝内12-14/外16-18/内20-24/外30-32、中山ダ24-25、東京芝16-18/23-24/ダ13-14、
                    中京ダ18-19、京都芝内14-16/外14-18/内外2000/外22-24/外30-32/ダ18-19、阪神芝16-18/24-26/30-32、小倉芝17-18。

(2) 指数の偏差値計算・欠損・新馬除外ルールと順位帯（shisu/indicators.py, hensachi.py）
  ■ 小さいほど良い指数：展開、想定前半、想定後半（0は値なし扱い）。タイムMは大きいほど良い。
  ■ 新馬戦を除外する指数：ZI、吉馬6指数。
  ■ ZI特例と安井0欠損ルール：ZIの0は同レース非ゼロ平均に置換。安井（ランク・5大ステータス）の0は欠損扱い（体力・やる気は0有効）。
  ■ レース除外：同一レースで欠損2頭以上、または全頭同値はレースごと除外。取消・除外馬は計算から外す。
  ■ 偏差値帯（6区分）： 71以上 / 66~70 / 61~65 / 51~60 / 41~50 / 40以下
  ■ 順位帯（新8区分）：
    ・s1（細区分5帯・排他）  ： 1位 / 2~3位 / 4~5位 / 6~9位 / 10位~
    ・s2（広区分3帯・重複あり）： 1~3位 / 1~5位 / 6位~

(3) 22条件の導出ルール（shisu/conditions.py）
   1. 時期（12-2月 / 3-5月 / 6-9月 / 10-11月）
   2. 輸送距離（110km以内 / 111-350 / 351-500 / 501-600 / 600km超 / 滞在）
   3. レース間隔（連闘 / 中2-3 / 中4-6 / 中7-9 / 中10-20 / 中21週以上）
   4. 叩き良化（休み明け(1戦) / 叩き2戦 / 叩き3戦 / 叩き4戦 / 叩き5戦以上）
   5. コース属性（R値帯、直線距離帯、初角距離帯、CFS帯、F係数帯、今走クワドラント）
   6. 左右回り・遷移（左 / 右、左→左 / 右→左 / 左→右 / 右→右）
   7. 距離帯（芝短 / 芝マイル / 芝中 / 芝クラシック / 芝長 / ダ短 / ダマイル / ダ中 / ダ長）
   8. 坂（坂あり / 坂なし）
   9. 前走クワドラント
  10. 当日斤量（51以下 / 51.5-53 / 53.5-55 / 55.5-57 / 57.5-59 / 59.5以上）
  11. 斤量増減（同じ / +0.5~+1.5 / +2kg以上 / -0.5~-1.5 / -2kg以下）
  12. 牝馬限定（牝馬限定 / 混合）
  13. 距離増減（同距離 / 延長200 / 延長400 / 延長400超 / 短縮200 / 短縮400 / 短縮400超）
  14. 前走着順・前走人気・前走上がり3F順（新8区分 s1 / s2）
  15. 前走脚質（逃げ / 先行 / 中団 / 後方）
  16. 前走R印3（HHH~HH / H / M / S / SS~SSS）

6. 条件ヒット馬の分類基準と WEDGE の見方
--------------------------------------------------------------------------------
(1) 条件ヒット馬（/entries/hits）の4分類ロジック（上から順に判定）
  1. 消し候補（keshi）：[全オッズ帯] 件数≥20 かつ 複勝率_val<5% かつ 掲示板率_val<10% ／ [odds10uのみ] 件数≥20 かつ 複勝率_val<20%
  2. 絶対軸（abs）    ：件数≥10 かつ 連対率_val≥80% かつ（複勝回収値≥100 または 単勝適正回収値≥100）
  3. 軸候補（axis）   ：件数≥10 かつ [複勝80%・掲示板90% / 連対60%・掲示板90% / 複勝70%・掲示板80%・複回100 / 連対50%・掲示板80%・複回100]
     ＋【高回収率の基準】オッズ帯が「10倍未満」「10〜50倍」のときだけ（2026-11-12〜）：
        件数≥30 かつ 複勝35%・掲示板50% かつ（複勝回収値≥200 または 単勝適正回収値≥200）
        件数≥30 かつ 複勝50% かつ（複勝回収値≥150 または 単勝適正回収値≥150）
  4. 相手候補（opp）  ：件数≥30 かつ [複勝60%・掲示板70% / 連対50%・掲示板70% / 複勝33%・複回150・掲示板50%]

  ■ 希少条件の最低件数の緩和（2026-11-12〜）
    結合データに「G1」「重賞」「準OP・OP」「芝長」「ダ長」のどれかを含む条件は、レース数そのものが少ないので最低件数を下げます：
      絶対軸・軸候補 10 → 6 ／ 相手候補 30 → 15 ／ 消し候補 20 → 12 ／ 高回収率の基準 30 → 15
    （「×」で区切った部品が完全に一致するときだけ。「1勝・OP」は対象外）

  ■ 新しい基準を全部の行に効かせるには
    基準は画面を開くたびに DB の行に当てるので、DB に入っている行にはすぐ効きます。ただし集計のコンパクト化（--compact）は
    「集計した時点の基準」で行を残しているので、新しい基準で初めて区分に入る行（高回収率の軸・希少条件の少ない件数の行）は、
    WEDGE の上位か基本コース固定（layer A）の行でない限り DB にありません。全部出すには集計からやり直します（1章 A の Step 2 → Step 4。
    --resume でも、基準が変わったことを検知して全部の master を作り直します）。

  ■ 条件ヒット馬の画面の見方（2026-11-12〜）
    ・同じ馬・指数・パターン・結合データで、オッズ帯「通常」とオッズ帯別（10倍未満・10〜50倍・50倍以上）が同じ区分に当たり、
      件数の差が3件以内のときは「通常」の行を出しません（中身がほぼ同じ馬の集まりで重なるため。馬ごとの該当数にも数えません）。
    ・並びは 10倍未満 → 10〜50倍 → 50倍以上 → 通常（行数が多くて表示を絞るときも、通常の行をいちばん後回しにします）。
    ・「10〜50倍」「50倍以上」で絶対軸・軸候補に当たった行は、行全体を赤の太字・薄い赤の背景で出します（狙い目の穴馬）。
    ・表はそれぞれ枠の中でスクロールし、見出しの行は上に固定されます。
    ・いちばん上の「指数クロス好走馬」＝ 絶対軸・軸候補が複数の指数で同時に出ている馬。「何指数以上」「指数A・Bの両方」で絞れ、
      「該当馬だけを下の表に出す」で4区分の表もその馬だけにできます。
    ・出馬表（/entries/race）の「指数クロス」＝ 複数の指数で同時に上位（順位3位以内 または 偏差値61以上）の馬。

  ■ 人気馬（10倍未満）の「買える／危険」の見分け（2026-11-13〜。条件ヒット馬の画面だけ。DB は変えていません）
    (a) 過剰人気カット（既定で ON）
        絞り込みフォームのチェック「10倍未満（odds10u）の軸・相手は回収値100以上のみ（過剰人気カット）」。
        オッズ帯が「10倍未満」の 軸候補・相手候補 のうち、複勝回収値も単勝適正回収値も 100 未満の行（当たっても増えない
        過剰人気の条件）を除いてから、4区分の表・馬ごとの該当数・指数クロス好走馬を数えます。
        ・画面の上に「過剰人気カット中: 軸候補 n 行・相手候補 m 行を除いています」と出ます。
          横の「カットせずに全部表示する」を押す（またはチェックを外して「絞り込む」）と全部の行に戻ります。
        ・絶対軸（もともと回収値100以上が条件）・消し候補・10倍未満以外のオッズ帯は対象外です。
        ・カットした10倍未満の行と同じ条件の「通常」の行（同じ区分・件数の差3件以内）は、もともと重なる行として出していないので、
          カット ON でも出ません（同じ過剰人気の条件が「通常」として出直さないように。その「通常」の行の回収値が100以上でも同じ）。
          件数が4件以上違う「通常」の行は別の情報なので、回収値に関係なく残ります。
        ・URL の引数は cut_low_10u=1（ON）／ cut_low_10u=0（OFF）。引数が無ければ ON です。
    (b) 消し(10倍未満) の行数と指数数
        「指数クロス好走馬」と「馬ごとの該当数」の両方に、オッズ帯「10倍未満」の消し候補の行数と、それが出た指数の数の列があります。
        指数クロス好走馬の右端のタグは、同じ指数で 軸 と 消し(10倍未満) の両方が出ていると
          「SAV 1 / 2 (消3)」（= SAV で 絶対軸1行・軸候補2行、同じ SAV で 消し(10倍未満) 3行）
        のように (消n) が付き、青紫の枠になります（その指数の中で評価が割れている、という印）。
    (c) 判定（軸の行数 = 絶対軸 + 軸候補 と、消し(10倍未満) の行数の比べ方）
        ・⚠️消優勢（青紫）: 消し(10倍未満) が1行以上あり、軸の行数以上（軸が0行で消しだけの馬も含む）
        ・要注意（グレー）: 軸があり、消し(10倍未満) が軸の行数の半分以上
        両方の表の「判定」の列と行の背景色、4区分の表の馬名の横にバッジで出ます。
        判定も (a) のカットのあとの行数で付けるので、カット ON のほうが「回収値の伴わない軸しか無い人気馬」が消優勢になりやすくなります。
        → 判定なし・(消n) なしで軸の指数数が多い馬が「買える人気馬」、⚠️消優勢・要注意の馬が「疑ってかかる人気馬」の目安です。
      基準（順位だけ・偏差値だけ・両方）と指数数・指数A・Bで絞れます。表では順位3位以内が太字、偏差値61以上が緑の背景。

(2) WEDGE / adjusted_WEDGE（/entries/wedge）の定義と見方
  ・WIN （決定力）      = (1着×3.0 + 2着×1.5 + 3着×1.0) / (件数 × 3.0)
  ・EDGE（期待値超え率）= 単勝オッズ帯別の期待着順以内に入った馬の割合
  ・WEDGE（通算）       = WIN + EDGE（1.00以上=トップ級[濃緑] / 0.80以上=優秀[薄緑] / 0.62=平均 / 0.50未満=下位）
  ・adjusted_WEDGE（旬）= 直近最大10年のうち「年間10件以上」ある年のみを対象に、減衰率0.65で加重平均した値。
  ・WEDGE一覧の画面は、開くとすぐ「馬 × 指数」の表（adj 最大 / adj 平均 / WEDGE 最大 / WEDGE 平均 と指数ごとの値）が見えます。
    指数・パターンのチェックボックスは「指数・パターンの絞り込みを開く」を押すと出ます（選択中の数は見出しに表示）。
    表の見出しの行はスクロールしても上に固定されます。

7. よくあるつまずき＆トラブルシューティング
--------------------------------------------------------------------------------
  Q. 集計（Step 2）が途中で止まった（Docker が落ちた・Mac がスリープした・Ctrl+C）
  A. --clean を外して --resume を付けて同じコマンドを実行してください。済んだ master は飛ばして残りから再開します。

  Q. 条件ヒット馬の軸候補・相手候補が前より少ない／人気馬の軸が消えた
  A. 過剰人気カット（既定 ON）で、10倍未満の軸候補・相手候補のうち回収値100未満の行を除いています（6章(1)）。
     画面の上の「カットせずに全部表示する」で元の全部の行が見られます。DB の中身は変わっていません。

  Q. 条件ヒット馬で「通常」の行が前より少ない
  A. オッズ帯別の行と同じ区分・件数の差3件以内の「通常」の行は、重なるので出していません（6章(1)）。
     省いた行数は画面の上に出ます。全部の行は WEDGE 一覧の CSV（オッズ帯「すべて」）で見られます。

  Q. 馬体重発表後の --mining-only が数秒で終わらない日がある
  A. 騎手の乗り替わり・取消などマイニング以外が変わっていると、自動で全部の指数を照合し直します（[INFO] に理由が出ます）。
     結果は正しいので、そのまま待ってください。

  Q. CLI（python ingest.py）の取得を途中で止めたい
  A. Ctrl-C で止まります（同時に取得中でも、各取得元が次のアクセスの前に止まります。2026-11-13 に修正。
     それ以前は同時取得中の Ctrl-C が効かず、最後まで取りに行っていました）。画面（/ingest）は「中止」ボタンです。

  Q. 指数の取得（/ingest）を前のように1つずつ順番に動かしたい
  A. 画面は常に同時に取得します。CLI なら `python ingest.py --sources … --sequential` で順番に実行できます。

  Q. 条件ヒット馬・WEDGE一覧に出る行が前より少ない
  A. コンパクト化（--compact）により、4区分にも高WEDGEにも入らない平凡な行を省いているためです。
     条件ヒット馬の4区分と WEDGE 1.0以上のトップ級行、および基本コース固定（layer A）の行は100%残っています。
