※過去データ（7,770万行）は作り直さず、今週の指数と出馬表だけを数秒で反映します。
※過去走のマイニング（タイムM・対戦M）は毎週取得する必要はありません（半年〜1年ごとの更新時のみ）。

【事前準備】プロジェクトフォルダへ移動し、Webアプリを起動しておく
  cd ~/Downloads/self-dev/docker/shisu/docker_shisu_replace
  docker run --rm -p 127.0.0.1:8000:8000 -v "$(pwd)":/app csv_processor_shisu python app.py

--------------------------------------------------------------------------------
STEP 1：今週の「外部指数」を取得して ext_indices/ に揃える（※出馬表処理の前に必須）
--------------------------------------------------------------------------------
出馬表を処理する前に、今週分の外部指数データを ext_indices/ に揃えます。

  ① スクレイピング指数（オメガ・keibaAI・かよちん・吉馬6種）＆ 安井サロンExcel：
     1. TARGET「出馬表分析」→「★5タブ」で今週の全レースを全選択し、ベースCSVを
        `ingest_in/base/` に出力する（必須列：レースID(新), 日付S, 枠番, 馬番, ワーク1）。
        ※安井サロンExcelがある場合は `ingest_in/yasui/` に置く。
     2. ブラウザで http://localhost:8000/ingest を開く。
     3. ベースCSV（と安井Excel）を選び、取得したい指数（①Ω・②吉馬・③かよちん・④keibaAI）に
        チェックを入れて実行する（keibaAIは開始ID・終了IDを入力）。
     → 選んだ取得元は【同時に】取得します（サイトが別なので待ち時間が重ならない。全体の時間は
        いちばん遅い取得元の時間ほど。サイトごとのアクセス間隔は今までどおり守ります）。
        ログは行ごとに「Ω指数:」「吉馬:」などの取得元の名前が付きます。
     → 取得完了と同時に、自動的に `ext_indices/` の各指数フォルダへ格納されます。

  ② TARGET・外部ソフトから取得する指数（StridePlus 12種・ZI・GoldAirplane・BCindex）：
     最新の指数CSVファイルを、手動で `ext_indices/` 配下の各フォルダに配置してください。
     ・StridePlus（sav, st, gokei, tenkai, siagari, senko, tsuiso, jikyu, jizoku, shunpatsu, mae_stime, ato_stime）
       → `ext_indices/StridePlus/`
       ※ボーダーのファイル（st_border*.csv・siagari_border*.csv など名前に border の付くもの）は
         一緒に置いたままで構いません。指数としては読みません（ST指数・仕上りを上書きしません）。
     ・ZI → `ext_indices/ZI_DATA/`
     ・GoldAirplane → `ext_indices/GoldAirplane/`
     ・BCindex → `ext_indices/BCindex/`

--------------------------------------------------------------------------------
STEP 2：TARGETから今週の「出馬表CSV」を出力して entries_in/ に置く
--------------------------------------------------------------------------------
  TARGETで「開催ひらく」→「JV一括取得」→「マイニング予想」
  →「出馬表分析」→「★4タブ」→ **【重要】「マイニングの読み込み」を実行**
  → 右クリック「全て選択する」→「選択範囲をファイルに出力（CSV）」で `entries_in/` に保存。
  （ファイル名例：`entries_in/shisu_20261108_1.csv`）

  ※注意：マイニング（タイムM・対戦M）は外部CSVではなく、この出馬表CSVの列から直接取得します。
          必ず★4タブで「マイニングの読み込み」を行ってからCSV出力してください。
          （それ以外の外部指数1〜4をTARGET側で読み込む必要はありません。STEP 1で揃えた
            `ext_indices/` からプログラムが自動で全馬に結合します）

--------------------------------------------------------------------------------
STEP 3：出馬表の偏差値計算 ＆ DB反映（別タブで2コマンド実行）
--------------------------------------------------------------------------------
Webアプリを起動したまま、ターミナルの別タブ（Cmd + T）で以下の2つを実行します。

  # 1) 出馬表に ext_indices/ の全外部指数を結合し、偏差値・順位・帯を計算する
  docker run --rm -v "$(pwd)":/app csv_processor_shisu python calc_entry_hensachi.py --merge-only --clean

  # 2) DBの出馬表と事前照合（xjoin）だけを更新する（古い出馬表は --prune で自動削除）
  docker run --rm -v "$(pwd)":/app csv_processor_shisu python build_db.py --entries-only --prune

  → 完了後、ブラウザで http://localhost:8000/entries を開けば、今週の出馬表・条件ヒット馬・WEDGE一覧が見られます！

--------------------------------------------------------------------------------
STEP 4：【当日・馬体重発表後】マイニング確定値が出たら出馬表を差し替える（差分更新）
--------------------------------------------------------------------------------
レース当日（馬体重発表と同じタイミング）にマイニングの「確定値」が出たら：
  1. TARGETの★4タブでマイニング（確定値）を読み込み直し、`entries_in/` の出馬表CSVを上書き出力する。
     （※外部指数はすでに `ext_indices/` にあるため再取得不要）
  2. 以下の2コマンドを実行する（--mining-only ＝ タイムM・対戦M だけの差分更新）：

  docker run --rm -v "$(pwd)":/app csv_processor_shisu python calc_entry_hensachi.py --mining-only
  docker run --rm -v "$(pwd)":/app csv_processor_shisu python build_db.py --entries-only --mining-only

  → Webアプリは起動したままでOK。ブラウザをリロードするだけで確定値が反映されます。

  ・--mining-only がすること：
      calc_entry_hensachi … STEP 3 で作った entries_out/entries_merged_hensachi.csv を読み、ext_indices/ は読み直さずに、
                            タイムM・対戦M の値・順位・偏差値・帯と、馬体重・増減などの基本の列だけを入れ替えて上書きします。
                            ほかの外部指数の列（計算済み）はそのまま残ります。
      build_db            … 出馬表のテーブルを入れ替え、事前照合（xjoin）は タイムM・対戦M の行だけを消して照合し直します
                            （ほかの約31指数の行は触りません。時間は全部やり直すときのおよそ 2/33）。
  ・--mining-only は `--indicators タイムM,対戦M` の短縮形です（`--indicators オメガ指数` のようにほかの指数も指定できます）。
  ・マイニング以外も変わっていたときは、自動で全部の計算・全部の照合に切り替わります（結果は STEP 3 と同じ。時間だけ STEP 3 並みにかかります）：
      calc_entry_hensachi … STEP 3 を一度も実行していない（統合ファイルが無い）／出馬表に馬が増えた・レースから馬が消えた
      build_db            … 騎手の乗り替わり・枠・前走の条件・ほかの指数の順位など、照合に関わる値が前の照合のときから変わっている
                            ／成績表を作り直したあと／前の実行が途中で止まったあと／前の版で作った照合結果（最初の1回だけ）
    どちらに切り替わったかは、実行時の [INFO] の行に出ます。つまり STEP 4 はいつもこの2コマンドで構いません。



--mining-only だけだと「タイムM・対戦M」の2指数しか見ないため、本日追加した安井式のデータが無視されてしまいます。
しかし、--mining-only に加えて --indicators で安井の8指数を指定すれば、他の24指数は一切再計算せず「マイニング2種＋安井8種」の計10指数だけを高速で差分更新できます。
STEP 3のように全34指数を1から計算し直す必要はありません（所要時間はフル実行の約3分の1以下で終わります）。
1. いま（または馬体重発表後に）実行するコマンド（マイニング2種 ＋ 安井8種のみ差分更新）

以下の2コマンドをそのままコピペして実行してください。

# 1) 統合出馬表の「タイムM・対戦M」と「安井8指数」だけを差し替える
docker run --rm -v "$(pwd)":/app csv_processor_shisu python calc_entry_hensachi.py --mining-only --indicators 安井_ランク,安井_スピード,安井_スタミナ,安井_パワー,安井_根性,安井_賢さ,安井_体力,安井_やる気

# 2) DBの照合結果（xjoin）も「タイムM・対戦M」と「安井8指数」の行だけを作り直す
docker run --rm -v "$(pwd)":/app csv_processor_shisu python build_db.py --entries-only --mining-only --indicators 安井_ランク,安井_スピード,安井_スタミナ,安井_パワー,安井_根性,安井_賢さ,安井_体力,安井_やる気

■ D. 半年〜1年ごとに過去データを追加するとき（raw_csv/ への配置）
------------------------------------------------------------------------
※過去走のマイニング（タイムM・対戦M）や前走データは、半年〜1年に1回まとめて追加します。
※TARGET ★6タブで追加の期間を出し、raw_csv/ に置くだけです（/ingest 画面の下部からアップロードも可）。
  replace_csv_ver3.py（下の A の Step 1）が最初に自動で csv_files/全場_タイムM.csv・全場_対戦M.csv に統合します。
  ・基本CSV：名前に「タイム」「マイニング」（→ タイムM）か「対戦」（→ 対戦M）を入れる（例 タイムM_2027前半.csv）。
    同じ馬（レースID(新)）は後のファイルの行を使い、最大10年分（データの最新年の9年前以降）を残します。
  ・前走の列パッチ：前走データ読込は時間がかかるので、基本CSVは前走なしで出し、前走の列だけを別のCSVにして置く（→ 2章F）。
  ・済んだファイルは raw_csv/merged_done/ に自動で移ります。


■ A. 過去レース集計データを更新したときのフルリビルド手順
------------------------------------------------------------------------
※長時間処理になるため、別タブで `caffeinate -di` を実行してMacのスリープを防いでから回してください。

# Step 1: 基本CSV＋外部指数の結合・正規化・偏差値・22条件（csv_files/ ＋ ext_indices/ → master_csv/）
docker run --rm -v "$(pwd)":/app csv_processor_shisu python replace_csv_ver3.py --clean --workers 2
  ・raw_csv/ に未統合のファイルがあれば、最初に csv_files/全場_*.csv へ統合・前走の列パッチを反映します。
  ・result_indices/ に結果指数（SP指数・ST指数）があれば、過去SP・ST の8指数の master も作ります（→ 2章G）。
  ・race_marks/ に外部レース印CSVがあれば、前走条件（前走メンバーLv・前走タイムLv・前走クッション帯・前走含水率帯）を付け、
    前走R印3 の空欄をペース判定で補います（→ 2章H）。近5走の条件（近5走同条件・近5走同場）は、基本CSVから自動で付きます（→ 2章I）。
  ・result_indices/ に結果指数があれば、SP・ST の3着内基準値（shisu/data/index_baseline_SP.csv・index_baseline_ST.csv）を
    直近の年を重くして作り直し、基準比の条件（前走SP基準比・過去SP今走基準比・過去SP3走順 など6つ）を付けます（→ 2章J）。

# Step 1.5（年1回の条件見直し時のみ）: 全掛け合わせ候補を採点して、使う family を選ぶ（→ 5章）
#   (a) 採点（重い。代表の指数で、all なら約5時間/master）
docker run --rm -v "$(pwd)":/app csv_processor_shisu python screen_families.py --space all --indicators タイムM,対戦M --workers 2 --export-selected
#       「指数なし（条件のみ）」のパターンも候補に入れるときは --tails RBAND,HBAND,NONE を付ける（→ 5章）
#   (b) 選抜基準だけやり直す（0.5秒。採点済みの screening_report.csv から再選抜）
docker run --rm -v "$(pwd)":/app csv_processor_shisu python screen_families.py --from-report --min-axis 1 --top-a 30 --export-selected

# Step 2: ベイズ集計＋WEDGE算出（master_csv/ → agg_csv/agg_master_{地域}_{指数名}.csv.gz）
docker run --rm -v "$(pwd)":/app csv_processor_shisu python aggregate_stats_ver2.py --clean --workers 2 --compact-min-count none --compact-min-wedge 1.0
  ・途中で止めた（Ctrl+C 等）ときは、--clean を --resume に変えれば済んだ master を飛ばして続きから再開できます：
      docker run --rm -v "$(pwd)":/app csv_processor_shisu python aggregate_stats_ver2.py --resume --workers 2 --compact-min-count none --compact-min-wedge 1.0

  ・2026-11-14 にオッズ帯「10倍未満」を「2〜10倍未満（2.0倍以上 10.0倍未満）」に変えました。この Step 2 を次に回したときから
    成績表に反映されます（--resume でも全部の master を集計し直します。→ 6章(1)）。

# Step 3: 出馬表の偏差値計算・1ファイル統合（entries_in/ → entries_out/entries_merged_hensachi.csv）
docker run --rm -v "$(pwd)":/app csv_processor_shisu python calc_entry_hensachi.py --merge-only --clean

# Step 4: DBの完全再構築（agg_csv/ ＋ entries_out/ → racing.db）
docker run --rm -v "$(pwd)":/app csv_processor_shisu python build_db.py --fresh


--------------------------------------------------------------------------------
2. TARGETからの入力CSV作成手順と、外部指数CSVの置き方
--------------------------------------------------------------------------------

＜A. 過去レースの基本CSV（csv_files/ または raw_csv/ に置くファイル）＞
  TARGETから出すのは次の2本だけです（★6タブ形式）。
  （1）レース検索 → ★6タブ（頭数10頭以上・障害レースを含めない条件で検索）
  （2）外部指数の欄に ①マイニング（タイムM）を読み込んで「レース一覧★画面イメージ（csv形式）」で出力
  （3）同じく ②対戦型マイニング（対戦M）で出力
  ・出力する列に「単勝配当」（単勝オッズの隣）と「複勝配当」（複勝シェアの隣）を追加しておくこと。
  ・追加の期間は raw_csv/ に置けば replace が csv_files/全場_タイムM.csv・全場_対戦M.csv に統合します。

＜B. 外部指数CSV群（ext_indices/ に置くファイル）＞
  ext_indices/ の下に、フォルダ名かファイル名で指数が分かるように置きます。
  ┌──────┬────────────────────────────┬──────────────────────────────────┐
  │ 形式 │ ファイルの中身                         │ 対象の指数（置き方の例）                             │
  ├──────┼────────────────────────────┼──────────────────────────────────┤
  │  A   │ レースID(新)18桁, 指数値               │ オメガ指数（OMEGA/）、かよちん指数（kayochin/）、    │
  │      │ ※/ingest から自動コピーされる形式     │ keibaAI指数（keibaAI/）、吉馬6指数（kichiuma/）、    │
  │      │                                        │ 安井8指数（yasui/）                                  │
  ├──────┼────────────────────────────┼──────────────────────────────────┤
  │  B   │ 旧ID10桁, 指数値, 順位（見出しなし）   │ StridePlus/ の下でファイル名の先頭で判定：          │
  │      │ 例 0520380101,54,6                     │  sav, st, gokei, tenkai, siagari, senko, tsuiso,     │
  │      │                                        │  jikyu, jizoku, shunpatsu, mae_stime, ato_stime      │
  ├──────┼────────────────────────────┼──────────────────────────────────┤
  │  C   │ 12桁レースID, 馬1指数, 馬1順位, …      │ Gold（GoldAirplane/ または gold*.csv）              │
  ├──────┼────────────────────────────┼──────────────────────────────────┤
  │  D   │ 旧8桁レースID, 馬1指数, 馬2指数, …     │ BC（BCindex/）、ZI（ZI_DATA/）                       │

＜C. 今週の出馬表CSV（entries_in/ に置くファイル）＞
  開催ひらく → JV一括取得 → マイニング予想 → 出馬表分析 → ★4タブ → マイニングの読み込み
  → 右クリック → 全て選択する → 選択範囲をファイルに出力（CSV）
  （ファイル名例：shisu_YYYYMMDD_1.csv。マイニング値だけの1本でよい）

＜D. 外部指数スクレイピング用のベースCSV（ingest_in/base/ に置くファイル）＞
  ・過去走取得時：レース検索の★7タブ（障害除く）で出力。
  ・今週分取得時：出馬表分析の★5タブで全選択して出力。
  ・必須列：「レースID(新), 日付S, 枠番, 馬番, ワーク1」（※他の列が混ざっていても可）

＜E. ラップ指数計算用のラップCSV（ingest_in/lap/ に置くファイル）＞
  ・レース検索（障害除く）→ ★5タブで編集 → ワークデータ1に「レースのラップタイム」を読み込みCSV出力。
  ・必須列：「レースID(新), 日付S, 場所, 芝・ダ, 距離, クラス名, 年齢限定, 着順, 着差, 補正, レース印２, ワーク1」

＜F. 前走の列パッチCSV（raw_csv/ に置くファイル）＞
  TARGET の「前走データ読込」は時間がかかるので、基本CSV（A）は前走を読み込まずに出し、前走の列だけを
  別のCSVで出して raw_csv/ に置くと、全場_タイムM.csv と 全場_対戦M.csv の両方の同じ馬の行に横結合（補完）されます。
  （1）基本CSVと同じ抽出条件（頭数・障害・期間）でレース検索 → ★6タブ → 前走データ読込
  （2）出力する列を「レースID(新)」と前走の列（間隔・休み明け～戦目・前走場所・前芝・ダ・前距離・前走斤量・前走人気・
       前走着順・前走脚質・前走上り3F順・前走レース印３・前走レースID(新) など）だけにして CSV 出力
       ※「指数」列は入れないこと（「指数」列の無いCSVを列パッチとして自動判別します）
  （3）raw_csv/ に置いて replace_csv_ver3.py を実行（または /ingest 画面の下の欄で「統合する」）

＜G. 結果指数（SP指数・ST指数）→ 「過去3走/5走の平均・最高」の8指数（result_indices/ に置くファイル）＞（2026-11-17〜）
  SP指数・ST指数はレースのあとに確定する値なので、そのレースの値をそのまま指数にはしません（未来の情報になるため）。
  各レース・各馬について「そのレースの日より前・600日以内の走」の直近3走・5走の平均と最高を計算して、次の8指数にします:
    過去SP_3走平均・過去SP_5走平均・過去SP_3走最高・過去SP_5走最高・過去ST_3走平均・過去ST_5走平均・過去ST_3走最高・過去ST_5走最高
  （1）置くファイル（result_indices/ の下。サブフォルダ・ZIP の中も探します。大文字小文字は問いません）
       ・SP指数: 名前が SP で始まる CSV（例 SP01260101.csv）／ speed*.zip の中の SP*.csv
       ・ST指数: 名前が st_se で始まる CSV（例 st_se_20261010.csv）／ st_se*.zip の中の CSV
       ・中身は見出しなしの2列「レースID(新)18桁, 指数値」（例 202610100504030705,80。-10 などの負の値も値として使います）
       ・同じ馬の値が複数のファイルにあれば、名前の順で後のファイルの値を使います
  （2）過去走の履歴は csv_files/ の基本CSV（全場_タイムM.csv を優先）から作ります。馬は 血統登録番号（10桁）で見分け、
       列が無ければ馬名で見分けます。取消・除外で走っていないレース、その指数の値が無いレース、障害は数えません。
       ★ 基本CSVに「馬場状態」「年齢限定」「血統登録番号」の列を入れて出しておくと、条件どおりに絞れます（2章A の出力に追加）。
  （3）対象の走の決め方
       ・2歳戦・3歳限定戦（年齢限定が 2歳・3歳。列が空なら 新馬・未勝利、レース名の「3歳…」などで判定。3上・4上 は対象外）
         → 600日以内の全部の走
       ・それ以外（古馬戦）→ 今走の 芝ダ・距離・馬場状態（良 / 稍・重 / 不 の3区分）と比べて、次の順に、最初に1走以上
         見つかった段階の走だけを使います（1〜2走しか無くても、その走だけで計算。0走のときだけ次の段階へ）
           ① 同じ芝ダ・距離差400m以内・同じ馬場状態（今走の馬場状態が分からなければ ② から）
           ② 同じ芝ダ・距離差400m以内
           ③ 距離差400m以内（今走の馬場状態が分かれば、同じ馬場状態も）
           ④ 同じ芝ダ
           ⑤ 600日以内の全部の走
       ・平均は小数第2位を四捨五入して小数第1位まで（54.0 は 54）。対象の走が無い馬は 0（空）で、0 は欠損として扱います
         （順位・偏差値の計算から外れます。同じレースに欠損が2頭以上いると、そのレースはその指数では使いません）。
         対象の走があるのに値がちょうど 0 になった馬は、欠損と区別するために 0.1 にしています。
  （4）使い方
       ・過去側（年1回のフルリビルド）: result_indices/ に置いて replace_csv_ver3.py（1章A の Step 1）を回すと、
         8指数の master（master_全場_過去SP_3走平均.csv.gz など）と、馬ごとの履歴 master_csv/__horse_perf_history__.csv.gz ができます。
         あとは Step 2 以降をいつもどおり（ほかの外部指数と同じに集計・照合されます）。計算しないときは --no-past-perf
         （ext_indices/past_sp_st/ に /ingest の出力があれば、ほかの外部指数と同じにそこから付きます）。
       ・出馬表側（毎週）: calc_entry_hensachi.py が、出馬表の各馬について同じ規則で8指数を計算して付けます（履歴のファイルを読むので速い。
         result_indices/ や基本CSVが変わっていれば、自動で履歴を作り直します）。
         今走の馬場状態はレース前には分からないので、想定を指定できます:
             docker run --rm -v "$(pwd)":/app csv_processor_shisu python calc_entry_hensachi.py --merge-only --clean --baba-turf 良 --baba-dirt 稍・重
           --baba-turf（芝）・--baba-dirt（ダ）= auto / 良 / 稍・重 / 不。auto は出馬表の「馬場状態」の列（無ければ指定なし ＝ ② から）。
           省くと、下の /ingest の画面で前に選んだ値（past_perf_settings.json。無ければ auto）を使います。
       ・/ingest の画面: 「1. 取得元」の下に「想定馬場状態（過去SP・ST指数用）」のプルダウン（芝・ダ それぞれ
         自動（出馬表の列／無ければ指定なし）/ 良 / 稍・重 / 不）があります。取得元「過去SP・ST指数」にチェックして実行すると、
         ベースCSVの各馬の8指数を計算して、TARGET 取込用CSV（ingest_out/…/past_sp_st/）を出し、ext_indices/past_sp_st/ にも置きます。
         ここで選んだ値は保存され、calc_entry_hensachi.py の既定になります。
         ※ この取得元のベースCSVには、馬名（または血統登録番号）・芝ダ・距離・年限定 のある出馬表CSV（entries_in/ に置く形）を選んでください。
       ・CLI: python ingest.py --sources past --base entries_in/shisu_YYYYMMDD_1.csv --baba-turf 良 --baba-dirt 不
  （5）注意
       ・直近の走を反映するには、その走が「基本CSV」と「結果指数のファイル」の両方に入っている必要があります。
         基本CSV（raw_csv/ への追加）を半年〜1年ごとにしか足さないと、その間のレースは「過去走」に入りません
         （例: 半年前までの基本CSVなら、直近半年の走は無いものとして計算されます）。直近の走まで使いたいときは、
         先週までの基本CSV（★6タブ。指数は読み込まなくてよい）を raw_csv/ に足して replace を回してください。
       ・過去側は実際の馬場状態、出馬表側は想定の馬場状態で絞ります（想定が外れると、過去の成績表と条件が少しずれます）。
       ・基本CSVに「年齢限定」の列が無いと、3歳限定の1勝クラス・オープン・重賞を見分けられず、古馬戦として絞り込みます
         （警告が出ます。出馬表は「年限定」で判定するので、そのレースでは過去側と条件がずれます）。
       ・結果指数のファイルを直した・足したときは、calc_entry_hensachi.py が自動で履歴を作り直します（中身が変わったかを毎回確かめます）。


＜H. 外部レース印5種（race_marks/ に置くファイル）→ 前走条件（2026-11-17〜）＞
  TARGET の外部レース印（メンバーレベル・タイムレベル・ペース判定・クッション値・ゴール前含水率）を、
  各馬の「前走のレース」で引いて、前走条件（集計キーの部品）として使います。
  （1）置き場所とファイル名
       ・race_marks/ の下（サブフォルダ・ZIP の中も探します。大文字小文字は問いません）
           member*.csv          メンバーレベル（レースレベル）   例 member2026.csv
           time*.csv            タイムレベル                     例 time2026.csv
           pace_decision*.csv   ペース判定（pace*.csv でも可）   例 pace_decision2026.csv
           cushion*.csv         クッション値                     例 cushion2026.csv
           moistureG*.csv       ゴール前含水率（moisture*.csv でも可。moistureC*.csv（4コーナー）は使いません）
       ・中身は TARGET の出力のまま（見出しなしの3列）:
           "2026年3回福島2日目12R",RX03263212,"0E Ｂ "      ← 開催名, RX+旧8桁のレースID, 2桁のカラーコード+値
         文字コードは cp932・UTF-8 のどちらでも読めます。同じレースが複数のファイルにあれば、名前順で後のファイルの値。
       ・含水率のファイルは、同じレースが2行続きます（1行目 = 芝の含水率、2行目 = ダートの含水率）。
  （2）できる前走条件（値が無い・印が「－」「----」の馬は空 → その条件を含むキーは作りません）
       ・前走メンバーLv    : A / B / C / D / E
       ・前走タイムLv      : S / A / B / C / D / E
       ・前走クッション帯  : 前走が芝のときだけ  軟(8.9以下) / 標準(9.0~9.9) / 硬(10.0以上)
       ・前走含水率帯      : 前走が芝 → 芝乾(9.9以下) / 芝標準(10.0~14.9) / 芝湿(15.0以上)
                             前走がダ → ダ乾(4.9以下) / ダ標準(5.0~9.9) / ダ湿(10.0以上)
       ・前走R印3 の補完   : 基本CSV・出馬表の「前走レース印３」が空の馬だけ、ペース判定（HHH/HH → HHH~HH、H、M、S、SS/SSS → SS~SSS）で埋めます。
                             値が入っている馬は、基本CSV・出馬表の値のまま（そちらが優先）。
  （3）使い方
       ・過去側: race_marks/ に置いて replace_csv_ver3.py（1章A の Step 1）を回すと、master にこの列が入り、
         印の表が master_csv/__race_marks__.csv.gz にも保存されます。読まないときは --no-race-marks。
         別のフォルダを読むときは --marks-dir フォルダ。パスワードつきなど読めない ZIP は、その1本だけ飛ばします（[WARN] が出ます）。
       ・出馬表側（毎週）: build_db.py が、出馬表の各馬の前走（「前走開催」の欄から作るレースID）で同じ値を引きます。
         race_marks/ にファイルがあればそれを読みます（無ければ master_csv/__race_marks__.csv.gz）。
         ※ replace を --no-race-marks や --marks-dir で回したときは、build_db.py も自動で同じ読み方になります
           （master と出馬表で違う印を見ないように、読み方を master_csv/__race_marks__.json に残しています）。
         → 先週のレースが前走の馬にも付くように、race_marks/ のファイルは毎週 TARGET から出し直して上書きしておいてください
           （過去側の作り直しは要りません。Step 4 の build_db.py --entries-only だけで反映されます）。
       ・この条件を使ったパターン（family）は、screen_families.py（Step 1.5）の候補に入ります。集計に使うには
         Step 1 → Step 1.5（選抜）→ Step 2 → Step 4 の作り直しが要ります。
  （4）注意
       ・照合は「年の下2桁・場所・回・日・R」で行います（RX… には月日が入っていないため）。基本CSVの 前走レースID(新) が
         無い馬（前走が地方・海外など）は空です。
       ・値の先頭2文字が16進（0〜9・A〜F）なら、必ずカラーコードとして取り除きます（TARGET の出力は必ず付いています）。
       ・クッション値・含水率が 0 以下・数でないときは「値なし」として扱います。

＜I. 近5走の同条件・同場での好走実績（近5走同条件・近5走同場。2026-11-17〜）＞
  各馬の「そのレースの日より前・600日以内」の走を新しい順に最大5走取り、その中の好走実績を1つの条件にまとめます
  （条件を細かく掛け合わせずに、適性の有無を1つの部品として使うためのもの）。
       ・近5走同条件 : 5走のうち「今走と同じ芝・ダ かつ 距離差200m以内」の走の最高着順
                       同条件連対あり（1〜2着）/ 同条件3着あり / 同条件4着以下 /（該当する走が無ければ空）
       ・近5走同場   : 5走のうち「今走と同じ場所 かつ 同じ芝・ダ」の走の最高着順
                       同場連対あり / 同場3着あり / 同場4着以下 /（該当する走が無ければ空）
  ・元は G と同じ「馬ごとの過去走の履歴」（csv_files/ の基本CSVから作る master_csv/__horse_perf_history__.csv.gz）です。
    結果指数（result_indices/）が無くても作られます。ファイルを置く作業はありません。
  ・過去側は replace_csv_ver3.py、出馬表側は build_db.py が同じ関数で付けます。
  ・失格・中止は「走ったが着なし」として4着以下に数えます。取消・除外・障害の走は数えません。
  ・注意は G と同じです: 過去走に数えられるのは「基本CSVにある走」だけです。基本CSVを半年前までしか足していないと、
    直近半年の走は無いものとして「近5走」を数えます（出馬表側も同じ履歴を使うので、両側の数え方は揃います）。
    基本CSVに 血統登録番号 の列が無いと、馬は馬名で見分けます。

＜J. SP指数・ST指数の「3着内基準値」と、基準比の条件（2026-11-18〜）＞
  「この条件のレースで3着に入る馬の SP指数・ST指数はどのくらいか」を基準値として持ち、前走の指数・過去走の指数を
  その基準値と比べた結果を条件（キーの部品）にします。ファイルを置く作業はありません（結果指数は G のとおり result_indices/ に）。

  （1）基準値マスタ（shisu/data/index_baseline_SP.csv・index_baseline_ST.csv）
       ・セル = 芝ダ × クラス13区分（2歳未勝利・3歳未勝利・2歳1勝・3歳1勝・古馬1勝・2勝・3勝・2歳OP・3歳OP・古馬OP・
         2歳重賞・3歳重賞・古馬重賞）× 馬場区分（芝: 良／良以外、ダ: 良稍／重不良）× 場所区分（主場 = 東京・中山・京都・阪神・中京／
         ローカル = 函館・札幌・福島・新潟・小倉）× 距離帯（芝: 〜1400 短距離・〜1800 マイル・〜2400 中距離・2401〜 長距離／
         ダ: 〜1300 短距離・〜1600 マイル・〜2000 中距離・2001〜 長距離）
       ・作り方: 3着馬の指数（0 は除く。新馬・G1・障害は入れない）を集め、セルごとに上位1/3を除いた平均を取り、
         件数の少ないセルは上の階層（L3 = 芝ダ×クラス×馬場 → L2 = ＋距離帯 → L1 = ＋場所区分）の値へ寄せます（縮約。K=30）。
       ・【直近の年を重く】平均は「最新の年 1.0・1年前 0.65・2年前 0.42・3年前 0.27 …」の重みつきです（decay 0.65）。
         等重みにするなら --baseline-decay 1.0（replace）／ --decay 1.0（下の更新コマンド）。
       ・引き方: L1 → L2 → L3 の順で最初にあるセル。G1 は同じ世代の「重賞」のセルで引き、新馬戦には基準値がありません。

  （2）基準値の更新（自動）
       ・replace_csv_ver3.py（1章A の Step 1）が、result_indices/ に SP・ST の結果指数があれば毎回作り直します。
         ログ: [INFO] 基準値（SP）: 3着馬 n 件（最新年 2026・decay 0.65・全体平均 62）→ 467 セル を … に書きました
       ・3着馬の標本が 2,000 件に満たないときは作り直しません（数か月ぶんのデータで10年ぶんの基準値を置き換えないため）。
         そのときは今のファイルをそのまま使います。下げるなら --baseline-min-samples N、作り直させないなら --no-baseline-update。
       ・基準値だけ作り直すコマンド（中身を見るだけなら --update を外す）:
           docker run --rm -v "$(pwd)":/app csv_processor_shisu python -m shisu.baselines --update
         ※ これだけでは master・出馬表には効きません。Step 1（replace）→ Step 2 → Step 4 を回してください。
       ・shisu/data/ の2つの CSV は Git で管理しているファイルです。replace が書き換えると git の差分に出ます（そのままで構いません。
         元に戻すなら git checkout shisu/data/index_baseline_SP.csv shisu/data/index_baseline_ST.csv）。

  （3）付く条件（6つ。分からない馬は空 → その条件を含むキーは作りません）
       ・前走SP基準比 : 前走のSP指数 − 前走の条件の基準値。+3以上 = 前走SP基準突破／0〜+2 = 前走SP基準クリア／
                        −5〜−1 = 前走SP基準未達／−6以下 = 前走SP基準大幅未達
       ・前走ST基準比 : +2以上 = 前走ST基準突破／0〜+1 = 前走ST基準クリア／−3〜−1 = 前走ST基準未達／−4以下 = 前走ST基準大幅未達
       ・過去SP今走基準比 : 今走の条件の基準値に対して、過去SP の 3走平均か5走平均が届いていれば SP平均基準超／
                        届かず3走最高が届けば SP3走最高基準超／5走最高だけ届けば SP5走最高基準超／どれも届かなければ SP今走基準未達
       ・過去ST今走基準比 : 同じ形（ST平均基準超／ST3走最高基準超／ST5走最高基準超／ST今走基準未達）
       ・過去SP3走順・過去ST3走順 : 指数「過去SP_3走平均」「過去ST_3走平均」のレース内順位。キーでは順位帯になります
                        （SP3走1位・SP3走2~3位・SP3走1~3位・SP3走1~5位・ST3走6位~ など）

  （4）使い方（他の指数との掛け合わせ）
       ・例: 「過去ST今走基準比 × 過去ST3走順 × 指数順位帯」のパターンは、オメガ指数の成績表なら
         「ST平均基準超×ST3走1~5位×1~5位」（最後の 1~5位 がオメガ指数の順位帯）という結合データになります。
       ・初期セットには入っていません。Step 1.5（screen_families.py）で候補に入るので選抜するか（→ 5章）、
         selected_families.json に手で書きます:
           {"name": "X_stb_st3", "parts": ["過去ST今走基準比", "過去ST3走順"], "tail": "RBAND"}
       ・「過去SP3走順」を含むパターンは、指数「過去SP_3走平均」そのものの成績表では作りません（同じ順位を2回掛けるだけなので。ST も同じ）。

  （5）過去側と出馬表側
       ・過去側（Step 1）: 前走は「基本CSVにある、その馬の前走レースID(新) の走」。今走の馬場は実際の馬場状態。
       ・出馬表側（build_db.py）: 過去SP・ST の値と順位は calc_entry_hensachi.py が付けた列から、基準値は master を作ったときの写し
         （master_csv/__index_baseline_*__.csv）から引きます。今走の馬場は想定です:
           docker run --rm -v "$(pwd)":/app csv_processor_shisu python build_db.py --entries-only --baba-turf 良 --baba-dirt 重
         （auto／良／稍／重／不／稍・重。省くと /ingest の「想定馬場状態」で選んだ値、それも無ければ出馬表の 馬場状態 の列・無ければ 良）
       ・基本CSVには クラス名・年齢限定・馬場状態・血統登録番号・前走レースID(新) の列を入れて出してください（G・I と同じ）。
         年齢限定 が無いと、3歳限定の1勝クラス・オープン・重賞の世代が分からず、そのレースの基準値が引けません。

3. システム全体像（内部で何をしているか）
--------------------------------------------------------------------------------
本システムは、過去データ側（replace / aggregate）と当日の出馬表側（calc_entry_hensachi / build_db）で
【完全に同一の共通パッケージ（shisu/）】を通して正規化・偏差値化・22条件・キー生成を行うことで、
表記ゆれの無いキー突合を実現しています。

  [Step 0] raw_csv/ の統合（replace_csv_ver3.py の最初・/ingest の画面）
  [Step 1] replace_csv_ver3.py（外部指数の結合・正規化・偏差値化・22条件 → master_csv/）
  [Step 1.5] screen_families.py（全掛け合わせ候補の採点・選抜 → selected_families.json）
  [Step 2] aggregate_stats_ver2.py（family × オッズ4区分集計・ベイズ推定・WEDGE算出 → agg_csv/）
  [Step 3] calc_entry_hensachi.py（出馬表への外部指数の結合・偏差値・帯付与＆横結合 → entries_out/）
  [Step 4] build_db.py（SQLite化・unified_all 統合・xjoin 事前構築 → racing.db）

5. 全掛け合わせ候補の自動選抜（screen_families.py）
--------------------------------------------------------------------------------
  ・採点済みレポート（screening_report.csv）から選抜基準を変えて selected_families.json を作り直す場合（0.5秒）：
    docker run --rm -v "$(pwd)":/app csv_processor_shisu python screen_families.py --from-report --min-axis 1 --top-a 30 --export-selected
  ・既定（--min-axis 25 --top-a 100）では約1,655通り（1,243 family）、--min-axis 1 --top-a 30 では4,868通り（3,531 family）が選ばれます。
  ・2026-11-17 から、候補を作る条件に6つ（前走メンバーLv・前走タイムLv・前走クッション帯・前走含水率帯・近5走同条件・近5走同場）が
    増えました。候補の数は --space default で 2,098 → 2,791通り、--space all で 7,557 → 10,815通り になり、採点の時間もその分かかります
    （上の「選ばれる数」は前の候補での数字です。採点し直すと変わります）。
  ・2026-11-18 から、さらに6つ（前走SP基準比・前走ST基準比・過去SP今走基準比・過去ST今走基準比・過去SP3走順・過去ST3走順 → 2章J）が
    増えました。--space default で 2,791 → 3,709通り、--space all で 10,815 → 15,195通り です。
    「過去SP今走基準比 × 過去SP3走順 × (前走SP基準比／前走着順／前走人気／近5走同条件)」と ST の同じ組も候補に入ります。
  ・【指数なし（条件のみ）のパターン】（2026-11-17〜）
    指数の順位・偏差値帯を使わず、コース・騎手・枠・条件だけの掛け合わせで絶対軸・軸候補・消し候補になるパターンも作れます。
      docker run --rm -v "$(pwd)":/app csv_processor_shisu python screen_families.py --space all --tails RBAND,HBAND,NONE --indicators タイムM,対戦M --workers 2 --export-selected
    ・--tails は候補の末尾の種類です（RBAND = 指数順位帯・HBAND = 偏差値帯・RANK = 指数順位・NONE = 条件のみ。既定は RBAND,HBAND）。
    ・条件のみのパターンは指数に依らないので、採点も本集計（Step 2）も「地域ごとに基準の master 1本」（タイムM、無ければ 対戦M、
      それも無ければその地域の先頭）だけで行い、その master の全部の馬（指数の欠けた馬も）を数えます。
      成績表は agg_csv/agg_master_{地域}_条件のみ.csv.gz の1本にまとまり、画面では指数の欄が「条件のみ」になります
      （指数の数だけ同じ成績表ができることはありません）。
    ・条件のみのパターンには指数の帯が無いので、選抜の基準A（識別力）では選ばれず、基準B（絶対軸・軸候補のキーの数）で選ばれます。
      数えるのが基準の master 1本ぶんなので、--min-axis の基準は指数つきのパターンより厳しめに効きます。
    ・条件ヒット馬・WEDGE一覧・逆引きでは、ほかの行と同じに出ます。「指数が下位の条件を軸・相手にしない」の制限は掛かりません
      （末尾が指数ではないため）。逆引きは基準の master から取り出します。

6. 条件ヒット馬の分類基準と WEDGE の見方
--------------------------------------------------------------------------------
(1) 条件ヒット馬（/entries/hits）の4分類ロジック（上から順に判定）
  1. 消し候補（keshi）：[全オッズ帯] 件数≥20 かつ 複勝率_val<5% かつ 掲示板率_val<10% ／ [2〜10倍未満（odds10u）のみ] 件数≥20 かつ 複勝率_val<20%
  2. 絶対軸（abs）    ：件数≥10 かつ 連対率_val≥80% かつ（複勝回収値≥100 または 単勝適正回収値≥100）
  3. 軸候補（axis）   ：件数≥20 かつ [複勝80%・掲示板90% / 連対60%・掲示板90% / 複勝70%・掲示板80%・複回100 / 連対50%・掲示板80%・複回100]
                        （2026-11-14〜。それまで 件数≥10。消し候補と同じ20件にそろえました。絶対軸は 件数≥10 のまま）
     ＋【高回収率の基準】オッズ帯が「2〜10倍未満」「10〜50倍」のときだけ（2026-11-12〜）：
        件数≥30 かつ 複勝35%・掲示板50% かつ（複勝回収値≥200 または 単勝適正回収値≥200）
        件数≥30 かつ 複勝50% かつ（複勝回収値≥150 または 単勝適正回収値≥150）
  4. 相手候補（opp）  ：件数≥30 かつ [複勝60%・掲示板70% / 連対50%・掲示板70% / 複勝33%・複回150・掲示板50%]
  ※ 2〜4（絶対軸・軸候補・相手候補）は、指数が上位の条件だけ（2026-11-16〜。下の「指数が下位の条件を軸・相手にしない」）

  ■ 指数が下位の条件を軸・相手にしない（2026-11-16〜）
    騎手や前走の条件が強いと、指数そのものは下位（順位が低い・偏差値が低い）なのに率だけ高くて
    「絶対軸・軸候補・相手候補」に出ることがありました。これを区分から外します。
    ・見るのは結合データの末尾（「×」で区切ったいちばん後ろ ＝ 指数の順位・順位帯・偏差値帯）です。
        上位（今までどおり判定する）: 1位・2~3位・4~5位・1~3位・1~5位 ／ 71以上・66~70・61~65・51~60 ／ 指数順位 1〜5
        下位（軸・相手にしない）    : 6~9位・10位~・6位~ ／ 41~50・40以下 ／ 指数順位 6 以下（6, 7, 8 …）
    ・消し候補にはこの制限をかけません（指数が下位の条件こそ消しの対象なので、今までどおり全部を見ます）。
    ・基準は画面を開くたびに DB の行に当てるので、Webアプリを再起動すればすぐ効きます（DB の作り直しは要りません）。
      横断検索のプリセット「絶対軸・軸候補・相手候補」も同じ基準です。

  ■ 負の相関にある指数の「消し」を数えない（2026-11-16〜。条件ヒット馬の画面だけ）
    同じ取得元の中で、片方が高い馬はもう片方が低く出やすい指数の組があります（先行力の高い馬は瞬発力が低く出る など）:
        StridePlus : 先行・想定前半・ST指数  ⇔  瞬発・想定後半・追走・持久・持続
        吉馬       : 吉馬_先行力            ⇔  吉馬_末脚力
        安井式     : 安井_スピード          ⇔  安井_スタミナ・安井_パワー・安井_根性
    ある馬が片方の指数で「絶対軸」か「軸候補」に1行でも当たっていれば、その馬の、対になる指数の
    「2〜10倍未満だけの消し候補」（複勝率<20% の規則だけで消しになっている行）を除きます（どちら向きにも）。
    ・除いた行は、消し候補の表・馬ごとの該当数・消し(2〜10倍未満)の行数と指数数・⚠️消優勢／要注意の判定のどれにも入りません。
      画面の上に「負の相関にある指数の軸ヒットにより除外した消し候補 N 行」と出ます。
    ・除かないもの: 全オッズ帯共通の消し（複勝率<5% かつ 掲示板率<10% も満たす行）、通常・10〜50倍・50倍以上の消し、
      組に入っていない指数の消し、同じ側の指数どうし（先行と想定前半 など）。
    ・軸ヒットは、過剰人気カット（下の (a)）と重なる「通常」を除いたあとの行で見ます
      （カット ON で消える回収値100未満の軸しか無い指数は、軸ヒットに数えません）。

  ■ オッズ帯の区切り（2026-11-14〜。「10倍未満」→「2〜10倍未満」）
    過去レースの確定単勝オッズで成績を分けるオッズ帯は、次の4つです：
      通常（オッズで絞らない）／ 2〜10倍未満（2.0倍以上 10.0倍未満。内部の名前は odds10u のまま）／ 10〜50倍 ／ 50倍以上
    ・単勝 1.9倍以下の馬は「2〜10倍未満」に入れず、「通常」にだけ入ります（1倍台の馬で勝率・複勝率が上振れするのを防ぐため）。
    ・画面の表記はすぐ「2〜10倍未満」になりますが、中身（成績表の数字）が変わるのは、次に集計からやり直したときです
      （1章 A の Step 2 → Step 4。Step 1 の replace はやり直さなくて構いません）。
      それまでは、オッズ帯を出す画面（横断検索・条件ヒット馬・WEDGE一覧・キーの詳細）の上に
      「この DB の成績表は、オッズ帯の前の区切り（10倍未満。単勝2倍未満の馬も入る）で集計したものです」と出ます。
      集計し直して DB を作り直すと消えます。
    ・Step 2 を --resume で回しても、区切りが変わったことを検知して全部の master を集計し直します（前の区切りの成績表を混ぜません）。

  ■ 軸候補の最低件数 10件 → 20件（2026-11-14〜）
    10〜19件の少ない標本で率だけ高い条件を、軸候補にしないようにしました（消し候補の20件と同じ基準）。
    ・変わるのは上の 3. の4つの条件だけです。絶対軸（10件）・高回収率の基準（30件）・相手候補（30件）・消し候補（20件）と、
      下の希少条件の最低件数（軸候補 6件 など）はそのままです。
    ・10〜19件でも、絶対軸の条件（連対率80%・回収値100）を満たす行は今までどおり絶対軸に出ます。
    ・基準は画面を開くたびに DB の行に当てるので、Webアプリを再起動すればすぐ効きます（DB の作り直しは要りません。
      10〜19件の行は DB に残ったまま、軸候補の表に出なくなるだけです）。横断検索のプリセット「軸候補」も同じ基準です。
    ・軸候補の行が減るので、下の「⚠️消優勢・要注意」の判定も、1〜2行の消しでは付かない基準に変えています（→ (c)）。

  ■ 希少条件の最低件数の緩和（2026-11-12〜）
    結合データに「G1」「重賞」「準OP・OP」「芝長」「ダ長」のどれかを含む条件は、レース数そのものが少ないので最低件数を下げます：
      絶対軸 10 → 6 ／ 軸候補 20 → 6 ／ 相手候補 30 → 15 ／ 消し候補 20 → 12 ／ 高回収率の基準 30 → 15
    （「×」で区切った部品が完全に一致するときだけ。「1勝・OP」は対象外）

  ■ 新しい基準を全部の行に効かせるには
    基準は画面を開くたびに DB の行に当てるので、DB に入っている行にはすぐ効きます。ただし集計のコンパクト化（--compact）は
    「集計した時点の基準」で行を残しているので、新しい基準で初めて区分に入る行（高回収率の軸・希少条件の少ない件数の行）は、
    WEDGE の上位か基本コース固定（layer A）の行でない限り DB にありません。全部出すには集計からやり直します（1章 A の Step 2 → Step 4。
    --resume でも、基準が変わったことを検知して全部の master を作り直します）。

  ■ 条件ヒット馬の画面の見方（2026-11-12〜）
    ・同じ馬・指数・パターン・結合データで、オッズ帯「通常」とオッズ帯別（2〜10倍未満・10〜50倍・50倍以上）が同じ区分に当たり、
      件数の差が3件以内のときは「通常」の行を出しません（中身がほぼ同じ馬の集まりで重なるため。馬ごとの該当数にも数えません）。
    ・並びは 2〜10倍未満 → 10〜50倍 → 50倍以上 → 通常（行数が多くて表示を絞るときも、通常の行をいちばん後回しにします）。
    ・「10〜50倍」「50倍以上」で絶対軸・軸候補に当たった行は、行全体を赤の太字・薄い赤の背景で出します（狙い目の穴馬）。
    ・表はそれぞれ枠の中でスクロールし、見出しの行は上に固定されます。
    ・いちばん上の「指数クロス好走馬」＝ 絶対軸・軸候補が複数の指数で同時に出ている馬。「何指数以上」「指数A・Bの両方」で絞れ、
      「該当馬だけを下の表に出す」で4区分の表もその馬だけにできます。
    ・出馬表（/entries/race）の「指数クロス」＝ 複数の指数で同時に上位（順位3位以内 または 偏差値61以上）の馬。

  ■ 人気馬（2〜10倍未満）の「買える／危険」の見分け（2026-11-13〜。条件ヒット馬の画面だけ。DB は変えていません）
    (a) 過剰人気カット（既定で ON）
        絞り込みフォームのチェック「2〜10倍未満（odds10u）の軸・相手は回収値100以上のみ（過剰人気カット）」。
        オッズ帯が「2〜10倍未満」の 軸候補・相手候補 のうち、複勝回収値も単勝適正回収値も 100 未満の行（当たっても増えない
        過剰人気の条件）を除いてから、4区分の表・馬ごとの該当数・指数クロス好走馬を数えます。
        ・画面の上に「過剰人気カット中: 軸候補 n 行・相手候補 m 行を除いています」と出ます。
          横の「カットせずに全部表示する」を押す（またはチェックを外して「絞り込む」）と全部の行に戻ります。
        ・絶対軸（もともと回収値100以上が条件）・消し候補・2〜10倍未満以外のオッズ帯は対象外です。
        ・カットした2〜10倍未満の行と同じ条件の「通常」の行（同じ区分・件数の差3件以内）は、もともと重なる行として出していないので、
          カット ON でも出ません（同じ過剰人気の条件が「通常」として出直さないように。その「通常」の行の回収値が100以上でも同じ）。
          件数が4件以上違う「通常」の行は別の情報なので、回収値に関係なく残ります。
        ・URL の引数は cut_low_10u=1（ON）／ cut_low_10u=0（OFF）。引数が無ければ ON です。
    (b) 消し(2〜10倍未満) の行数と指数数
        「指数クロス好走馬」と「馬ごとの該当数」の両方に、オッズ帯「2〜10倍未満」の消し候補の行数と、それが出た指数の数の列があります。
        指数クロス好走馬の右端のタグは、同じ指数で 軸 と 消し(2〜10倍未満) の両方が出ていると
          「SAV 1 / 2 (消3)」（= SAV で 絶対軸1行・軸候補2行、同じ SAV で 消し(2〜10倍未満) 3行）
        のように (消n) が付き、青紫の枠になります（その指数の中で評価が割れている、という印）。
    (c) 判定（軸の行数 = 絶対軸 + 軸候補 と、消し(2〜10倍未満) の行数・指数数の比べ方。2026-11-14 に基準を引き締め）
        ・⚠️消優勢（青紫）: 次の4つを全部満たす馬
              絶対軸が1行も無い ／ 消し(2〜10倍未満) が3行以上 ／ その消しが2つ以上の指数で出ている ／ 消しの行数が軸の行数より多い
        ・要注意（グレー）: 消優勢ではなく、次の3つを全部満たす馬
              軸が1行以上ある ／ 消し(2〜10倍未満) が2行以上 ／ 消しの行数が軸の行数以上
              （絶対軸のある馬は、消しがどれだけ多くても「要注意」までです）
        ・どちらでもない馬には何も付きません。たとえば 消しが1行だけの馬、軸が無くて消しが2行だけの馬、
          軸が無くて消しが1つの指数にしか出ていない馬（偶発的な消しの可能性が高いため）。
        （それまでの基準は「消しが1行でも軸の行数以上なら消優勢・半分以上なら要注意」でした。軸候補を20件以上に絞って
          軸の行が減ったので、そのままだと1〜2行の消しで警告だらけになるためです）
        両方の表の「判定」の列と行の背景色、4区分の表の馬名の横にバッジで出ます。
        判定も (a) のカットのあとの行数で付けるので、カット ON のほうが「回収値の伴わない軸しか無い人気馬」が消優勢になりやすくなります。
        → 判定なし・(消n) なしで軸の指数数が多い馬が「買える人気馬」、⚠️消優勢・要注意の馬が「疑ってかかる人気馬」の目安です。
      基準（順位だけ・偏差値だけ・両方）と指数数・指数A・Bで絞れます。表では順位3位以内が太字、偏差値61以上が緑の背景。

(2) WEDGE / adjusted_WEDGE（/entries/wedge）の定義と見方
  ・WIN （決定力）      = (1着×3.0 + 2着×1.5 + 3着×1.0) / (件数 × 3.0)
  ・EDGE（期待値超え率）= 単勝オッズ帯別の期待着順以内に入った馬の割合
  ・WEDGE（通算）       = WIN + EDGE（1.00以上=トップ級[濃緑] / 0.80以上=優秀[薄緑] / 0.62=平均 / 0.50未満=下位）
  ・adjusted_WEDGE（旬）= 直近最大10年のうち「年間10件以上」ある年のみを対象に、減衰率0.65で加重平均した値。
  ・WEDGE一覧の画面は、開くとすぐ「馬 × 指数」の表（adj 最大 / adj 平均 / WEDGE 最大 / WEDGE 平均 と指数ごとの値）が見えます。
    指数・パターンのチェックボックスは「指数・パターンの絞り込みを開く」を押すと出ます（選択中の数は見出しに表示）。
    表の見出しの行はスクロールしても上に固定されます。

(3) 逆引き（/entries/drill）と危険条件メモ（2026-11-16〜）
  条件ヒット馬の4区分の表と、WEDGE一覧の明細の表の「結合データ」のリンク、または右の「危険条件メモ / 調査」の列の
  「調査」を押すと、別タブで逆引きページが開きます。その条件（指数・パターン・オッズ帯・地域・結合データ）に当たった
  過去の馬を master_csv/ から取り出して並べるページです（DB も master も作り直さずに使えます）。
  ■ ページの中身（上から）
    1) ⚠️ 危険条件・死角メモ … 調べて分かった「この項目に当たっていたら危ない」を書いて「保存」。
         例: ⚠️馬体重478kg以下は危険 ／ ⚠️前走4角10番手以下は消し
       ・保存すると、条件ヒット馬・WEDGE一覧のその条件の行の「危険条件メモ / 調査」の列に、赤の太字で出ます。
         結合データのセルとメモのセルにマウスを置くと、全文が出ます（長いメモは表の中では200文字で切ります）。
       ・消すときは「このメモを削除」（または本文を空にして保存）。
       ・「全地域共通のメモにする」にチェックして保存すると、地域が違う同じ条件の行にも出ます
         （その地域だけのメモがあれば、そちらを優先して出します）。
       ・保存先はプロジェクト直下の condition_notes.json です（racing.db の外なので、build_db.py --fresh で DB を作り直しても
         消えません。バックアップはこのファイル1本をコピーするだけ。環境変数 NOTES_PATH で場所を変えられます）。
    2) TARGET 貼付用のレースID … 「全件／好走 1〜3着のみ／凡走 4着以下のみ」を切り替えて、
         左 = レースID(新) 18桁（馬単位）／ 右 = レースID(新/馬番無) 16桁（レース単位・重複なし）
       を「コピー」ボタンで丸ごとコピーできます。TARGET に貼って、馬体重・4角位置など master に無い項目を調べる用です。
       「明細CSVをダウンロード」で、取り出した行の全部の列を CSV（区分 = 好走／凡走／集計外 つき）で保存できます。
    3) コア分布サマリー … 項目（単勝オッズ・枠番・馬番・頭数・騎手・22条件 など）ごとに、当たった馬がどの値に集まっているか。
       ・コア（緑の枠）= 全体の80%以上が収まる範囲。数やオッズの帯は「連続したいちばん狭い範囲」、
         騎手・脚質などは「単独1件の値を除いて、件数の多い値から80%に届くまで」。
       ・危険候補 = コアの外の単独1件（点線。飛び地）と、凡走の集まり（赤。2件以上で、好走率が全体の半分以下）。
       ・各値は「値：件数（好走の数）」です。ここで目に付いた値を、上のメモに書いておく使い方です。
    4) 該当した過去走の明細 … 日付・場所・レースID・馬番・馬名・騎手・単勝オッズ・着順・指数値・順位・偏差値・22条件。
       緑の行 = 好走（1〜3着。1着は太字）／ 赤の行 = 凡走（4着以下・失格・中止）／ 灰色の字 = 取消・除外（集計外）。
       画面は新しい順に2,000行まで（全部は CSV）。
  ■ 件数について
    取り出し方は集計（aggregate_stats_ver2.py）と同じなので、ページの上の「成績表（DB）: 件数」と一致します。
    違うときは注意書きが出ます（成績表を集計したあとに master を作り直した・オッズ帯の区切りが前のままの DB など）。
    master_csv/ に その地域・指数の master が無いときは、逆引きは出ませんが、メモの登録と確認はできます。

(4) 条件特化ヒット（2026-11-17〜。条件ヒット馬のページの4区分の表の下）
  「指数が下位の条件を軸・相手にしない」（(1)）で4区分から外れた行のうち、件数・連対率・複勝率・掲示板率・回収値の基準は
  絶対軸・軸候補を満たしているもの ＝ 指数は下位でも、騎手・前走などの条件そのものが強い行を、別の表に出します。
  ・4区分の判定は変えていません（指数が下位の行は、今までどおり絶対軸・軸候補・相手候補になりません。消し候補になる行もここには出ません）。
  ・同じ馬に、同じ条件が指数の数だけ並ばないように、(馬番・パターン・スキーム・オッズ帯・地域・結合データから末尾を除いた部分)
    が同じ行は、複勝率_val が最大（同じなら件数が最大）の1行にまとめています。
      元区分 = その代表の行が満たしている基準（絶対軸 / 軸候補）
      指数数・指数（末尾）= その条件に当たった指数と、それぞれの末尾（6~9位・40以下 など）。太字は絶対軸の基準。
                             指数名を押すと、その指数の逆引きが別タブで開きます
  ・過剰人気カットが ON のときは、2〜10倍未満で複勝回収値も単勝適正回収値も100未満の行を、4区分の表と同じく除きます。
  ・件数・結合データ・「危険条件メモ / 調査」の列から、代表の行の逆引き（レースIDのコピー・メモの登録）を別タブで開けます。
  ・★ 表に出るのは DB に入っている行だけです。集計（1章A の Step 2）は既定で「平凡な行」を書かないので、
    2026-11-16 の変更（指数が下位の条件を軸にしない）のあとに集計し直した DB では、この表の行の多くが DB に入っていません。
    2026-11-17 から、集計はこの表の行も残すようにしました。次に Step 2 → Step 4 を回したときから全部出ます
    （区分の決まりが変わったので、--resume でも全部の master を集計し直します）。
    2026-11-16 より前に集計した DB なら、その行は残っているので、そのまま出ます。

7. よくあるつまずき＆トラブルシューティング
--------------------------------------------------------------------------------
  Q. 集計（Step 2）が途中で止まった（Docker が落ちた・Mac がスリープした・Ctrl+C）
  A. --clean を外して --resume を付けて同じコマンドを実行してください。済んだ master は飛ばして残りから再開します。

  Q. 条件ヒット馬の軸候補・相手候補が前より少ない／人気馬の軸が消えた
  A. 過剰人気カット（既定 ON）で、2〜10倍未満の軸候補・相手候補のうち回収値100未満の行を除いています（6章(1)）。
     画面の上の「カットせずに全部表示する」で元の全部の行が見られます。DB の中身は変わっていません。

  Q. 絶対軸・軸候補・相手候補の行が前より少ない（指数が下位の条件が出なくなった）
  A. 2026-11-16 から、結合データの末尾（指数の順位・順位帯・偏差値帯）が下位の条件
     （6~9位・10位~・6位~・41~50・40以下・指数順位6以下）は、絶対軸・軸候補・相手候補にしません（6章(1)）。消し候補は今までどおりです。

  Q. 消し候補の行が前より少ない／画面の上に「負の相関にある指数の軸ヒットにより除外した消し候補 N 行」と出る
  A. 先行と瞬発のように負の相関にある指数の組で、片方に軸があるとき、もう片方の「2〜10倍未満だけの消し」を除いています（6章(1)）。
     全部の行は WEDGE 一覧の CSV（「区分」列）で見られます。

  Q. 逆引き（/entries/drill）で「master がありません」と出る
  A. master_csv/ に master_{地域}_{指数名}.csv.gz がある環境で使えます（1章 A の Step 1 の出力）。メモの登録・確認は master が無くてもできます。

  Q. 過去SP・ST の8指数（過去SP_3走平均 など）が出馬表に付かない／master ができない
  A. result_indices/ に結果指数のファイル（SP*.csv・speed*.zip／st_se*.csv・st_se*.zip）があり、csv_files/ に基本CSV
     （全場_タイムM.csv など）がある状態で replace_csv_ver3.py を回してください（2章G）。ログに「結果指数 SP指数: n ファイル → m 頭分」と出ます。
     「レースID(新) 18桁, 指数値 として読めない行」の警告が出るときは、ファイルの1列目が18桁のレースID(新)になっているか確認してください。

  Q. 過去SP・ST の値が「0」の馬が多い／そのレースの順位・偏差値が空になる
  A. 対象の過去走（600日以内・その指数の値がある走）が無い馬は 0（欠損）です。新馬・休み明けのほか、基本CSVに入っていない
     期間の走は数えられません（2章G の注意）。同じレースに欠損が2頭以上いると、そのレースはその指数では使いません（ほかの 0=欠損 の指数と同じ）。

  Q. 想定馬場状態を変えて計算し直したい
  A. calc_entry_hensachi.py --merge-only --clean --baba-turf 稍・重 --baba-dirt 不 → build_db.py --entries-only（過去の成績表は作り直しません）。
     過去SP・ST の指数だけ差し替えるなら --indicators 過去SP_3走平均,過去SP_5走平均,…（指数名をカンマで並べる）でも構いません。

  Q. 前走メンバーLv・前走タイムLv・前走クッション帯・前走含水率帯が空の馬が多い
  A. (1) race_marks/ にその種類のファイルがあるか（replace・build_db のログに「レース印: メンバーレベル 1 本・… → n レース」と出ます）、
     (2) その馬の前走のレースがファイルに入っているか（前走が地方・海外・ファイルの期間より前なら空）、
     (3) 前走クッション帯は前走が芝の馬だけ、を確認してください。出馬表側は race_marks/ を毎週出し直しておくと、先週のレースが前走の馬にも付きます（2章H）。

  Q. 近5走同条件・近5走同場が空の馬が多い
  A. 600日以内の直近5走の中に、条件の合う走（同じ芝ダ・距離差200m以内／同じ場所・同じ芝ダ）が無い馬は空です（新馬・転向初戦など）。
     全部の馬が空なら、csv_files/ に基本CSV（全場_タイムM.csv など）があるか、master_csv/__horse_perf_history__.csv.gz ができているかを確認してください（2章I）。

  Q. 前走SP基準比・過去SP今走基準比などが空の馬が多い／全部空
  A. (1) 前走基準比: 前走が基本CSVに無い馬（地方・海外・障害・基本CSVの期間の外）、前走の結果指数が result_indices/ に無い馬、
         前走が新馬戦の馬は空です。(2) 今走基準比: 過去SP・ST の値が無い馬（新馬・長期休養明け）と、新馬戦は空です。
     (3) 全部空なら、replace のログに「[INFO] 基準値（SP）…」が出ているか、master_csv/__index_baseline_SP__.csv があるか、
         replace を --no-past-perf で回していないか（今走基準比と3走順が空になります）を確認してください（2章J）。
     (4) 出馬表側で 過去SP3走順 が空なら、calc_entry_hensachi.py の出力に 過去SP_3走平均_順位 の列があるかを確認してください。

  Q. 指数なし（条件のみ）のパターンを使いたい
  A. screen_families.py に --tails RBAND,HBAND,NONE を付けて選抜し（5章）、Step 2 → Step 4 を回してください。
     selected_families.json に手で {"name": "N_jk_r5", "parts": ["騎手", "近5走同条件"], "tail": "NONE"} のように書いても使えます。
     画面では指数の欄が「条件のみ」になり、成績表は agg_csv/agg_master_{地域}_条件のみ.csv.gz に入ります。

  Q. 危険条件メモはどこに保存される？ DB を作り直したら消える？
  A. プロジェクト直下の condition_notes.json です。racing.db の外なので、build_db.py --fresh でも消えません（6章(3)）。
     「危険条件メモを読めません」と出たときは、このファイルを手で直したときの書き間違いなどです（上書きはしません。直すか、別名に変えてください）。

  Q. メモの「保存」を押すと 403 になる
  A. 画面を localhost・IP アドレス以外の名前（Mac のホスト名など）で開いていると、保存を断ります（外部指数の取得 /ingest と同じ安全策）。
     http://localhost:8000 で開くか、起動時に -e SHISU_ALLOWED_HOSTS=mymac.local のように、その名前を渡してください。

  Q. 軸候補の行が前より少ない／⚠️消優勢・要注意の馬が前より少ない
  A. 2026-11-14 に、軸候補の最低件数を 10件 → 20件 に上げ、それに合わせて消優勢・要注意の基準を引き締めました（6章(1)）。
     10〜19件の条件は軸候補に出ません（絶対軸の条件を満たす行は出ます）。消しが1行だけの馬には警告が付きません。

  Q. 条件ヒット馬で「通常」の行が前より少ない
  A. オッズ帯別の行と同じ区分・件数の差3件以内の「通常」の行は、重なるので出していません（6章(1)）。
     省いた行数は画面の上に出ます。全部の行は WEDGE 一覧の CSV（オッズ帯「すべて」）で見られます。

  Q. build_db.py（--entries-only や --mining-only）が「[entries] loaded: …」の直後に落ちる（Docker の Exit 137 ＝ メモリ不足）
  A. 2026-11-14 に修正しました。以前は事前照合（xjoin）で、1頭ぶんの照合結果（family × 指数 × キーで数十万行）と照合のキャッシュを
     まるごとメモリに持っていたため、family が数千・指数が34あると数 GB に膨らんでいました。今は照合結果を5,000行ずつ DB に書き、
     キャッシュも照合1回ごとに上限（2万件・5万行）を見るので、family・指数がいくつあってもメモリは一定です（結果と速さは同じ）。
     コードを更新するだけで効きます（Docker イメージの作り直しは不要）。進み具合は「[xjoin] …: 50/348 頭, hits …」と50頭ごとに出ます。

  Q. 画面の上に「この DB の成績表は、オッズ帯の前の区切り（10倍未満…）で集計したものです」と出る
  A. オッズ帯「2〜10倍未満」の成績表に、まだ単勝1倍台の馬が入っている、という知らせです（故障ではありません。6章(1)）。
     次のフルリビルド（1章 A の Step 2 → Step 4）で消えます。それまでは今までどおりの数字で使えます。

  Q. 条件ヒット馬・WEDGE一覧の上に「この出馬表の照合結果（下の行）は、今の成績表より前に作ったものです」と出る
  A. 成績表だけを作り直して（build_db.py --mode foragg）、出馬表の照合をやり直していないときに出ます。
     毎週の STEP 3 の 2) （build_db.py --entries-only）を実行すれば消えます。フルリビルド（--fresh）なら最初から出ません。

  Q. 馬体重発表後の --mining-only が数秒で終わらない日がある
  A. 騎手の乗り替わり・取消などマイニング以外が変わっていると、自動で全部の指数を照合し直します（[INFO] に理由が出ます）。
     結果は正しいので、そのまま待ってください。

  Q. CLI（python ingest.py）の取得を途中で止めたい
  A. Ctrl-C で止まります（同時に取得中でも、各取得元が次のアクセスの前に止まります。2026-11-13 に修正。
     それ以前は同時取得中の Ctrl-C が効かず、最後まで取りに行っていました）。画面（/ingest）は「中止」ボタンです。

  Q. 指数の取得（/ingest）を前のように1つずつ順番に動かしたい
  A. 画面は常に同時に取得します。CLI なら `python ingest.py --sources … --sequential` で順番に実行できます。

  Q. 条件ヒット馬・WEDGE一覧に出る行が前より少ない
  A. コンパクト化（--compact）により、4区分にも高WEDGEにも入らない平凡な行を省いているためです。
     条件ヒット馬の4区分と WEDGE 1.0以上のトップ級行、および基本コース固定（layer A）の行は100%残っています。
